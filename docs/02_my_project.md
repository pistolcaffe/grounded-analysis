# 선정 주제 — AI 판단의 신뢰 경계: 근거 추적성과 일관성

> 정체성: 에이전트 판단의 근거를 검증 가능한 출처에 강제로 묶고 독립적으로 재검증하는 메커니즘, 그리고 **그것이 작동하는 조건과 무너지는 조건의 경계를 규명**하는 것.

## 조준점 (흔들리면 여기로 돌아온다)

**문제** — 실행 전엔 검증 못 하고 실행하면 되돌릴 수 없는 판단 작업에서, 검증 능력 없는 사람은 에이전트 결론을 맹신하게 되고, 주고받는 과정이 그걸 자기 판단으로 착각시킨다. 아는 사람은 안 속고 모르는 사람만 속는데, 정작 에이전트가 필요한 건 모르는 사람이다.

**전제** — 원본 출처는 신뢰 가능한 바닥으로 둔다. 무한후퇴(근거의 근거의 근거…)는 범위 밖.

**해결** — 바닥에서 결론까지의 근거 사슬을 비전문가도 추적·검증할 수 있게 강제하고, 독립 검증기로 재검증하며, 사실과 추론을 분리한다. 검증의 부담을 "분야 지식"에서 "근거 추적"으로 옮긴다.

**경계 (심장)** — 검증 가능한 바닥이 있는 무대(데이터)에선 작동하고, 바닥이 없는 무대(콘텐츠)에선 무너진다. 이 경계 자체가 "AI 판단을 믿어도 되는 조건"을 정의한다.

## 신뢰의 두 기둥 (시뮬레이션으로 확인됨)

baseline은 두 종류의 신뢰를 동시에 무너뜨린다. 이 둘이 곱해지며 문제가 증폭된다.

- **수직 신뢰** — 이 답을 믿을 근거가 있는가. baseline은 근거가 불투명(검증된 건지 추측인지 모름).
- **수평 신뢰** — 이 답이 안정적인가. baseline은 비결정적(같은 데이터에 매번 다른 판단).

어떤 근거로 믿을지도 모르겠는데(수직), 그 판단마저 매번 바뀐다(수평). 딛고 설 게 없어진다. 이 시스템은 두 기둥을 동시에 회복한다.

## 문제를 관통하는 다섯 얼굴

- **검증 불가능성** — 데이터가 복잡해서 사람이 직접 못 푼다
- **정보 비대칭** — 아는 사람만 함정을 피하고, 모르는 사람은 속는다
- **판단 주체의 소실** — 과정이 남의 결론을 내 판단으로 착각시킨다
- **근거의 무한후퇴** — 근거의 근거는 누가 검증하나 (→ 전제로 배제)
- **비가역성** — 즉시 실행으로 확인되는 작업(예: 코드 실행)은 이 문제 밖. 경계를 그어준다

## 1. 문제 (누가·병목)

- **누가**: 에이전트에게 판단·해석을 맡기는 사람. 데이터를 주고 "인사이트 뽑아줘"를 묻는 실무자. 특히 그 분야를 잘 모르는 사람.
- **병목**: 에이전트가 그럴듯한 판단을 술술 내놓는데, 실제 근거에서 나온 건지 지어낸 건지 알 수 없고(수직), 게다가 물을 때마다 답이 다르다(수평). 다시 검증하지 않으면 못 믿고, 검증하면 쓸 이유가 없다. 과정에서 그 판단이 어느새 자기 판단인 것처럼 착각되어, 근거 없는 결정을 실행하게 된다.
- **바라는 것**: 모든 판단에 검증 가능한 근거가 강제로 붙고, 사실과 추론이 분리되며, 같은 데이터엔 같은 답이 나오는 것.

## 2. Metric (시뮬레이션 반영해 재정의)

baseline이 "우연히 잘하는 것(계산 정확도)"이 아니라 "구조적으로 못하는 것"을 잰다.

- **분리율 (자1)** — 각 주장이 "데이터로 검증됨 / 추론·해석·가정"으로 명시적으로 라벨링되어 있나. (수직 신뢰)
- **재검증율 (자2)** — 각 수치 주장이 원본에서 **독립 검증기**로 재계산·확인 표시되어 있나. 에이전트 자신의 계산은 자기참조라 불인정. (수직 신뢰)
- **일관성 (자3)** — baseline/final을 각각 여러 번 돌렸을 때 위 지표의 분산. baseline은 들쭉날쭉, final은 일관. (수평 신뢰)

보조로 traceability rate(사슬 완결)와 환각율을 함께 본다.
**경계 지표**: 두 무대(데이터 vs 콘텐츠)의 개선폭 차이 자체가 "경계가 여기 있다"의 증거.

## 3. 평가 케이스

### 성공 무대 — 데이터 (10케이스)
작은 합성 데이터셋 + 질문 + 정답(참인 주장 / 유혹적 거짓 주장). 합성이라 정답이 생성과 동시에 확보됨.

**시뮬레이션 교훈**: 데이터가 단순하면 요즘 상위 모델의 baseline이 계산은 잘한다(정확도 70%대). 그래서 난이도를 "모델이 계산을 틀리는 수준"으로 올리기보다, **metric을 baseline이 구조적으로 못하는 것(분리·재검증·일관성)으로** 겨냥한다. 난이도는 상관→인과 함정 등으로 적당히 올린다.

**어려운 케이스 1개**: 상관을 인과로 착각시키는 데이터. 모든 지표가 함께 움직여 공통 요인이 배후에 있을 수 있는 구조. "A가 B를 유발했다"고 단정하면 실패.

### 실패/경계 무대 — 콘텐츠 (3~5케이스, 맛보기)
스크립트 + 관련 영상 데이터. 근거를 강제해도 traceability가 잘 안 오른다는 것을 보이는 게 목적. "무엇이 참인 후킹인가"의 원본 바닥이 없어 사슬이 허공에서 끝나고, 독립 검증기로 재계산도 불가능(주관).

## 4. baseline vs final (실제 시뮬레이션 실측)

같은 데이터(8주 앱 지표, 상관→인과 함정 포함)에 baseline 프롬프트(그냥 "분석해줘")와 final 프롬프트(사실/추론 분리 + 원본·계산식 강제 + 가정 표면화 + 인과 단정 금지)를 각각 GPT·Gemini로 돌린 실측 결과:

| | GPT baseline | Gemini baseline | GPT final | Gemini final |
|---|---|---|---|---|
| 코드 실행 | X | O | X | O |
| 계산 정확도 | 정확 | 정확 | 정확 | 정확 |
| 인과 태도 | 유보~단정 | **단정("입증")** | 거부 | 거부 |
| 숨은 가정(그룹핑) | 안 다룸 | **위장** | 표면화 | **표면화** |
| 분리율 | ~12% | ~5% | ~95% | ~95% |
| 재검증 가능성 | ~0% | ~0% | ~95% | ~95% |

(분리율/재검증율은 손 채점 추정치. 코드 구현 시 자동 채점으로 정밀화 예정)

### baseline의 세 가지 실패 (실증됨)

1. **새 자로는 낮다 (분리율 5~20%, 재검증 0%)** — 개선 여지가 활짝 열림.
2. **코드 실행이 신뢰를 보장하지 않는다** — Gemini baseline은 코드를 돌렸지만 "캠페인" 그룹핑 같은 해석적 가정을 코드에 숨겨 사실로 위장했고, 인과를 더 강하게 단정("입증되었습니다")했다. tools(계산시키기)만으론 부족. 오히려 추론이 코드를 거치며 사실의 외피를 쓴다.
3. **비결정적이다** — 같은 데이터에 인과를 유보하기도(GPT), 단정하기도(Gemini) 한다. 비전문가는 자기가 받은 게 안전한 버전인지 위험한 버전인지 모른다. 순전히 운.

### final의 개선 (실증됨)

1. **분리 12→95%, 재검증 0→95%** — baseline이 구조적으로 0에 가깝던 걸 채움. 미미한 개선(70→78)이 아니라 극적 개선.
2. **가정이 표면화된다** — Gemini final은 baseline과 똑같이 코드를 돌렸지만, "[가정] W1,2,5,6과 W3,4,7,8을 임의로 그룹핑함"을 명시. 코드를 돌려도 가정이 더 이상 위장되지 않는다. (가설의 정확한 증명)
3. **비결정성이 결정성으로** — baseline은 세 응답이 제각각(분리율 5~20%, 인과 단정~유보)이었으나, final은 GPT·Gemini 모두 95%대·인과 거부·가정 표면화로 **수렴**. 어떤 모델이든 일관된 신뢰 형태로 모인다. baseline에서 제일 위험했던 Gemini까지 교정됨.

### 검증된 것 / 남은 것
- 프롬프트 수준 근거강제만으로 분리·가정표면화·인과거부는 거의 완성(~95%).
- 재검증은 "가능성 95%"(원본+계산식이 응답에 노출됨). **실제 자동 대조(100%)는 독립 검증기 코드가 완성.** 즉 프롬프트로 여기까지, 코드로 마무리.

## 5. Final 설계 (iteration = changelog)

각 iteration이 관찰된 실패에 대응. (숫자는 실제 돌려서 채운다)

- **Iteration 1 — 사실/추론 분리 강제 (skill)**: 모든 주장을 "데이터로 검증됨 / 추론·가정"으로 라벨링. "캠페인이라 묶었다" 같은 숨은 가정도 강제로 표면화. → 분리율↑
- **Iteration 2 — 근거 사슬 강제 (skill)**: 모든 주장을 "결론 + 계산 + 원본 참조" 세 마디로 출력. 근거 없는 결론 금지. → traceability↑
- **Iteration 3 — 독립 검증기 (verification)**: 에이전트와 **별개**의 결정론적 검증기가 각 수치를 원본에서 재계산해 대조. 자기참조 탈피. 계산이 어떤 가정 위에 있는지도 노출. → 재검증율↑
- **Iteration 4 — 일관성 확보**: 위 세 장치가 응답을 결정적으로 고정. 검증된 수치는 항상 같고, 추론은 강제 라벨돼 위험한 버전이 안 나온다. → 일관성↑ (여러 번 돌려 분산으로 측정)
- **뺀 실험 — orchestration**: 주장 종류별 에이전트 분업. 각자 부분만 봐서 전체 맥락(교란변수, 심슨의 역설) 놓침 → 하락 → 제거

**핵심 통찰**: final의 힘은 tools(계산)에 있지 않다. Gemini가 증명했듯 계산은 오히려 가정을 위장한다. 진짜 힘은 **사실/추론 분리 + 독립 재검증 + 그로 인한 결정성**에 있다.

## 6. 증명

- 데이터 무대 (실측): 분리율 ~12% → ~95%, 재검증 가능성 0% → ~95%, 비결정 → 결정(모델 무관 수렴). 독립 검증기 붙이면 재검증 실검증 100%로 완성 예정.
- 콘텐츠 무대 (예정): 근거강제해도 잘 안 오름 (tools 단계부터 막힘, "후킹"은 계산 검증 불가)
- **격차 = 경계.** 같은 메커니즘이 데이터에선 작동, 콘텐츠에선 무너짐.

## 7. Hot Take (프로젝트의 심장)

근거강제는 만능이 아니다. **검증 가능한 바닥이 존재하는 무대에서만 작동한다.** 그리고 신뢰 회복은 두 층이다 — 근거를 원본까지 강제 노출해 "믿을 근거"를 만들고(수직), 독립 재검증과 사실/추론 분리로 "매번 같은 답"을 만든다(수평). 특히 **코드를 실행시키는 것만으로는 신뢰가 오르지 않는다. 계산은 오히려 숨은 가정을 사실로 위장할 수 있다.** 인간이 AI 판단을 자기 판단으로 착각하는 건 근거가 안 보이고 답이 매번 바뀌기 때문이며, 근거를 실행 가능한 바닥까지 강제하고 답을 결정적으로 고정하면 비전문가도 판단 주체로 돌아온다. 에이전트에게 판단을 맡기기 전 물어야 할 것은 **"이 판단의 출처가 검증 가능한 바닥을 갖는가"**이다.

## 무대 조합 근거

- 성공: 데이터 (근거가 계산으로 참/거짓 딱 떨어짐 = 가장 검증 가능한 바닥)
- 실패: 콘텐츠 (근거 출처가 흐르고 판단이 주관적 = 바닥 없음)
- 부담되면: 성공 무대만 문서(공개 문서 = 고정 바닥)로 교체, 실패 무대는 콘텐츠 유지

## 제출물 대응 현황

- **1. 솔루션 코드 + changelog**: 설계 완료, baseline 시뮬레이션 완료. 실제 코드 구현 + 진짜 숫자로 changelog 채우기 필요
- **2. 재현 가이드**: 코드 나오면 커맨드 정리
- **3. 영상 5분**: 영어 스크립트 준비 필요 (서사: 세 번 돌려 매번 다른 답 → 근거·일관성 문제 → 해결 → 경계)
- **4. 궤적**: Claude Code 상시 사용 시 자동 축적

## 남은 실제 작업 순서

1. final 프롬프트(분리+사슬 강제) 설계해 같은 데이터에 돌려 지표 개선 확인
2. 독립 검증기(원본 재계산) 코드 구현
3. 채점 로직(분리율·재검증율·일관성) 구현
4. 합성 데이터 10케이스로 baseline/final 정식 측정, changelog 채우기
5. 콘텐츠 무대 맛보기로 경계 실측
6. 영어 영상 스크립트, 재현 가이드, 궤적 정리

## 구현 규모 감각

배포 제품이 아니라 **커맨드라인에서 돌아가는 스크립트 묶음**. 웹서비스·UI 없음.
- 에이전트를 부르는 스크립트 (수십 줄)
- 근거강제 구현: 에이전트 지시(skill) + 독립 검증기(진짜 코드다운 부분)
- 채점 스크립트 (분리율·재검증율·일관성)
- 합성 데이터셋 10개

독립 검증기(결정론적 재계산)와 채점 자동화에서 개발 실력이 차별점. 바이브 코더는 못 만드는 부분.
